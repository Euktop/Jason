# 📖 Справочник команд JasonUtils
Все **встроенные команды**, поставляемые с ядром `Jason` и утилитой `JasonUtils`.
> 💡 Команды регистрируются автоматически в `bootstrap.py`.
---
## 🧮 Базовые команды (ядро Jason)
### `print`
Выводит текстовое сообщение.
| Параметр  | Тип    | Обязателен | Описание          |
|-----------|--------|------------|-------------------|
| `message` | string | да         | Текст для вывода  |
```json
{"command": "print", "params": {"message": "Готово!"}}
```
### `add`
Складывает два числа.
| Параметр | Тип    | Обязателен |
|----------|--------|------------|
| `a`      | number | да         |
| `b`      | number | да         |
```json
{"command": "add", "params": {"a": 15.5, "b": 4.5}}
```
Результат: `20.0`
### `echo`
Возвращает текст без изменений. Параметр: `text` *(string)*.
### `sum`
Суммирует массив чисел. Параметр: `numbers` *(array)*.

## 📂 Файловые команды (JasonUtils)
Все файловые команды проходят проверку **Security Guard** (см. ниже).
### `create_file`
Создаёт файл. Если папок нет — создаёт их.
| Параметр  | Тип    | Обязателен | По умолчанию |
|-----------|--------|------------|--------------|
| `path`    | string | да         | —            |
| `content` | string | нет        | `""`         |
```json
{
"command": "create_file",
"params": {
"path": "JasonRun/input/hello.txt",
"content": "Привет, мир!"
}
}
```
### `modify_file`
Полностью перезаписывает файл.
| Параметр  | Тип    | Обязателен |
|-----------|--------|------------|
| `path`    | string | да         |
| `content` | string | да         |
```json
{
"command": "modify_file",
"params": {
"path": "JasonRun/input/hello.txt",
"content": "Перезаписано."
}
}
```
### `search_replace`
Ищет и заменяет текст в файле или рекурсивно в папке. Бинарные файлы пропускаются. Поддерживает расширенные опции поиска: регулярные выражения, учёт регистра, поиск целых слов, лимит замен и направление обхода.
| Параметр         | Тип    | Обязателен | По умолчанию      | Описание                                                                                      |
|------------------|--------|------------|-------------------|-----------------------------------------------------------------------------------------------|
| `path`           | string | да         | —                 | Путь к файлу или папке                                                                        |
| `search`         | string | да         | —                 | Строка поиска (или regex-паттерн, если `regex=true`)                                          |
| `replace`        | string | нет        | `""`              | Строка замены (для regex может содержать `\1`, `\2` и т.д.)                                   |
| `regex`          | bool   | нет        | `false`           | Использовать регулярные выражения                                                             |
| `case_sensitive` | bool   | нет        | `true`            | Учитывать регистр букв                                                                        |
| `whole_words`    | bool   | нет        | `false`           | Искать только целые слова (игнорируется при `regex=true`)                                     |
| `max_matches`    | number | нет        | `1`               | Максимум замен на файл. `0` = без ограничений (заменить все)                                  |
| `direction`      | string | нет        | `"top_to_bottom"` | Направление поиска: `"top_to_bottom"` (сверху вниз) или `"bottom_to_top"` (снизу вверх)       |

**Примеры:**
```json
{
"command": "search_replace",
"params": {
"path": "JasonRun/input",
"search": "старый",
"replace": "новый"
}
}
```
```json
{
"command": "search_replace",
"params": {
"path": "JasonRun/input/notes.md",
"search": "\\bfoo\\b",
"replace": "bar",
"regex": true,
"case_sensitive": false,
"max_matches": 0
}
}
```
```json
{
"command": "search_replace",
"params": {
"path": "JasonRun/input/log.txt",
"search": "ERROR",
"replace": "[FIXED]",
"whole_words": true,
"max_matches": 5,
"direction": "bottom_to_top"
}
}
```
**Логика параметров:**
- `regex=true` — `search` интерпретируется как регулярное выражение. В `replace` можно использовать группы `\1`, `\2` и т.д.
- `case_sensitive=false` — поиск без учёта регистра (`a` = `A`).
- `whole_words=true` — совпадение только на границах слов (`foo` найдёт `foo`, но не `foobar`). Игнорируется, если `regex=true`.
- `max_matches=N` — заменить не более N совпадений в каждом файле. `0` — заменить все.
- `direction="bottom_to_top"` — начинать замену с конца файла (полезно, например, для замены последних N записей в логе).

## 📖 Команды чтения (Read-only)
Команды для безопасного чтения файловой системы **без каких-либо изменений**. Обе команды проходят проверку **Security Guard** и не прерывают выполнение батча при ошибках — проблемные пути попадают в поле `error` результата.
---
### `read_files`
Читает содержимое нескольких файлов по массиву путей и возвращает **единый JSON-блок** — список результатов. Если файл не найден, недоступен или выходит за пределы Whitelist — для него формируется запись со статусом `error`, остальные файлы обрабатываются штатно.
| Параметр | Тип   | Обязателен | Описание                                |
|----------|-------|------------|-----------------------------------------|
| `paths`  | array | да         | Массив абсолютных путей к файлам        |
```json
{
"command": "read_files",
"params": {
"paths": [
"C:\\Users\\eukto\\Desktop\\Work\\My_notes\\note1.md",
"C:\\Users\\eukto\\Desktop\\Work\\My_notes\\note2.md"
]
}
}
```
**Формат вывода** (один блок на все файлы):
```json
[
{
"path": "C:\\...\\note1.md",
"status": "ok",
"content": "# Заголовок\nТекст заметки...",
"resolved": "C:\\Users\\eukto\\Desktop\\Work\\My_notes\\note1.md"
},
{
"path": "C:\\...\\note2.md",
"status": "error",
"error": "Файл не найден"
}
]
```
**Возможные статусы:**
- `ok` — файл прочитан, содержимое в поле `content`.
- `error` — в поле `error` указана причина: `Файл не найден`, `Путь не является файлом`, `Доступ запрещён`, `Файл не является текстовым (ошибка декодирования UTF-8)`.
---
### `list_files`
Читает структуру папок и возвращает **единый JSON-блок** со списком всех найденных файлов и папок (полные пути). Поддерживает контроль глубины вложения и фильтр по типу.
| Параметр | Тип    | Обязателен | По умолчанию | Описание                                                                 |
|----------|--------|------------|--------------|--------------------------------------------------------------------------|
| `paths`  | array  | да         | —            | Массив абсолютных путей к папкам                                         |
| `depth`  | number | нет        | `0`          | Глубина поиска. `0` = бесконечная рекурсия, `1` = только указанная папка |
| `type`   | string | нет        | `"all"`      | Фильтр: `"all"` / `"files"` / `"folders"`                                |
```json
{
"command": "list_files",
"params": {
"paths": ["C:\\Users\\eukto\\Desktop\\Work\\My_notes"],
"depth": 2,
"type": "all"
}
}
```
**Формат вывода** (один блок):
```json
{
"items": [
"C:\\...\\My_notes\\00 Входящие",
"C:\\...\\My_notes\\10 Панель управления",
"C:\\...\\My_notes\\00 Входящие\\заметка.md",
"C:\\...\\My_notes\\10 Панель управления\\Файл.md"
],
"errors": []
}
```
**Логика параметра `depth`:**
- `0` — бесконечная рекурсия, обход всех вложенных уровней.
- `1` — только содержимое указанной папки (без рекурсии в подпапки).
- `2`, `3`, ... — указанная папка + 1, 2, ... уровня вложенности.
**Логика параметра `type`:**
- `"all"` — в результат попадают и файлы, и папки.
- `"files"` — только файлы (но папки всё равно обходятся рекурсивно для поиска вложенных файлов).
- `"folders"` — только папки.
Результат автоматически сортируется: **папки идут перед файлами**, внутри групп — по алфавиту (с учётом русской локали). Недоступные по Security Guard элементы молча пропускаются и не попадают ни в `items`, ни в `errors`.

## 🛡 Система безопасности (Security Guard)
### Где настраивается
Два текстовых файла в папке `JasonRun/`:
| Файл              | Назначение                                |
|-------------------|-------------------------------------------|
| `white_list.txt`  | Разрешённые пути (если пуст — всё можно)  |
| `black_list.txt`  | Запрещённые пути (приоритет над белым)    |
### Формат файлов
```text
# Это комментарий — строки с # игнорируются
# Пустые строки тоже игнорируются
C:\Projects\MyApp\data
C:\temp\workspace
```
* Один путь = одна строка.
* Если указана **папка** — все вложенные файлы и подпапки наследуют правило.
* Пути приводятся к абсолютным автоматически (`Path.resolve()`).
### Правила
1. **Blacklist проверяется первым.** Если путь внутри запрещённой зоны — доступ заблокирован, даже если он есть в Whitelist.
2. **Whitelist.** Если файл не пуст, то путь **обязан** быть внутри одной из разрешённых зон.
3. **Directory Traversal.** Относительные пути вида `../../Windows/System32` раскрываются в абсолютные до проверки.
4. **Hot-reload.** Метод `guard.reload()` перечитывает оба файла без перезапуска.
### Пример
```text
# white_list.txt
C:\Users\eukto\Projects\JasonRun
# black_list.txt
C:\Users\eukto\Projects\JasonRun\logs
C:\Users\eukto\Projects\JasonRun\white_list.txt
C:\Users\eukto\Projects\JasonRun\black_list.txt
```
→ Можно работать со всем внутри `JasonRun`, **кроме** папки `logs` и самих файлов списков.
### Поведение при ошибке безопасности
| Режим               | Что происходит                                                    |
|---------------------|-------------------------------------------------------------------|
| Одиночный (`run`)   | Скрипт падает с `SecurityError`                                   |
| Пакетный (`batch`)  | Ошибка записывается в `"error"` поля результата, батч продолжается |
| `search_replace`    | Запрещённые файлы **пропускаются**, остальные обрабатываются       |

## 🧠 Obsidian-команды (работа с заметками)
Эти команды упрощают типовые операции с текстовыми файлами, особенно в базах знаний Obsidian. Все они также проходят проверку Security Guard.
### `set_frontmatter`
Добавляет или обновляет поля в YAML-блоке (frontmatter) в начале файла. Если блока нет – создаёт.
| Параметр | Тип   | Обязателен | Описание |
|----------|-------|------------|----------|
| `path`   | string| да         | Путь к файлу |
| `fields` | object| да         | Словарь с полями для добавления/обновления (значения могут быть любого типа) |
```json
{
"command": "set_frontmatter",
"params": {
"path": "заметка.md",
"fields": {
"tags": ["study", "archive"],
"status": "archive",
"updated": "2026-07-23"
}
}
}
```
### `insert_line`
Вставляет одну или несколько строк **до** или **после** первого вхождения шаблона (строка или регулярное выражение, если обрамлено `/`).
| Параметр | Тип    | Обязателен | По умолчанию | Описание |
|----------|--------|------------|--------------|----------|
| `path`   | string | да         | —            | Путь к файлу |
| `anchor` | string | да         | —            | Шаблон для поиска (строка или `/regex/`) |
| `position`| string| нет        | `"after"`    | `"before"` или `"after"` |
| `lines`  | array  | да         | —            | Список строк для вставки (каждая строка – отдельный элемент) |
```json
{
"command": "insert_line",
"params": {
"path": "заметка.md",
"anchor": "## Список запчастей",
"position": "after",
"lines": ["- [[Новая запчасть]]"]
}
}
```
### `append_to_list`
Добавляет элемент в конец маркированного, нумерованного или чек-листа. Можно указать заголовок (`section`), под которым искать список. Если `section` не указан, поиск идёт по всему файлу.
| Параметр | Тип    | Обязателен | Описание |
|----------|--------|------------|----------|
| `path`   | string | да         | Путь к файлу |
| `section`| string | нет        | Заголовок (строка, начинающаяся с `#`, например `## Архитектура`) |
| `item`   | string | да         | Текст нового элемента (может включать маркер `-`, `*`, `1.`, `- [ ]` и т.д.) |
```json
{
"command": "append_to_list",
"params": {
"path": "Чек-лист.md",
"section": "## 🏗 Архитектура",
"item": "- [ ] Проверить DIP"
}
}
```
### `touch`
Обновляет поле `updated` в frontmatter на текущую дату или на указанную. Если поля нет – создаёт. Может использоваться для автоматической отметки о последнем изменении.
| Параметр | Тип    | Обязателен | Описание |
|----------|--------|------------|----------|
| `path`   | string | да         | Путь к файлу |
| `date`   | string | нет        | Дата в формате `ГГГГ-ММ-ДД` (по умолчанию – сегодня) |
```json
{
"command": "touch",
"params": {
"path": "заметка.md"
}
}
```
### `glob`
Применяет набор команд ко всем файлам, соответствующим шаблону (с поддержкой `*` и `**`). Команды внутри **не должны** содержать ключ `path` – он подставляется автоматически для каждого найденного файла. Это мощное средство для массовых операций.
| Параметр | Тип    | Обязателен | Описание |
|----------|--------|------------|----------|
| `pattern`| string | да         | Шаблон пути (например, `"50 Архив/**/*.md"`) |
| `commands`| array | да         | Список команд (объекты с `command` и `params`) без поля `path` |
```json
{
"command": "glob",
"params": {
"pattern": "50 Архив/**/*.md",
"commands": [
{
"command": "set_frontmatter",
"params": {
"fields": { "status": "archive" }
}
},
{
"command": "touch",
"params": {}
}
]
}
}
```
> **Примечание:** Результат выполнения `glob` – массив результатов для каждого файла и каждой команды. В пакетном режиме ошибки внутри отдельных команд не прерывают выполнение всей `glob`.
---
## ⚠️ Обработка ошибок
Неверный тип данных или запрещённый путь → `CommandExecutionError` / `SecurityError`.
В пакетном режиме: `"error"` заполнен, `"result"` = `null`.
